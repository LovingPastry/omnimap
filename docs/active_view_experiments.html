    审计报告说 Fisher 少了一个平方，我们没有改

    诊断 · 不改动结论成立
    现象

    审计发现 LegacyFisherEvaluator 直接把 .grad 当作 Fisher 对角，没有 torch.square。按定义 Fisher 对角是 Σ J²，看起来像致命 bug。

    诊断

    沿调用链找到实际加载的光栅器（在仓库外的 FisherRF 目录），它的 CUDA backward 里 #define acc_func atomicAddSquare，每个像素的贡献在归约前已经平方。FisherRF 作者在 issue #5 里也说明 .grad 只是用来搬运结果。

    选型
    不选在 Python 里补 torch.square：会变成四次方。DiagFisherEvaluator 就是这么错的。 采用保持原样，把"平方在 kernel 里"写进记忆，防止以后再"修"。
    为什么重要

    后面所有实验都建立在这个信息量上。如果这里错了，掩码、步长、停止判据的结论全部作废。第一步先确认测量本身是对的。

    2026-09-05 · 讨论定路线

    真机上的四个症状，指向同一个根因

    诊断路线已全部实现（10-17）
    现象
    • 相机在北极附近打转，绕不出去。
    • 相机冲向半球下沿、桌面下方，或撞关节限位。
    • 速度大小靠试，实际由限幅决定。
    • 没有停止条件：真机配置 spherical_speed_min: 0.0，防抖停机永远不会触发。
    总诊断

    FisherRF 的信息增益是为"在自由空间的候选集里挑一张图"设计的。挑图不需要可行性、速度尺度和停止条件。我们把它拿来驱动受约束空间里的连续运动，这三样就都成了必需品。

    所以修法不是调参，而是给控制链补上缺失的部件。下面 03、05 章就是这些部件。

    定的顺序

    极点 → 停止判据 → 可达性掩码 → 尺度归一化。理由是：做对比实验之前，必须先修好"桌下"和"极点"，否则测到的是 bug 而不是方法。

    2026-09-13 · commit 2170d69 → 6b99a62

    极点打转不是局部最优，是坐标系把一个自由度压扁了

    算法改进 · 梯度参数化几何量成立质量收益未测出 · 真机未验证
    现象

    旧日志里 φ=87° 时东向与北向速度的各向异性约 3000×；phase4_dense 跑 50 步只到过 2/18 个经度分区。

    诊断

    (θ, φ) 参数化里 θ 自由度被两个独立的 cos φ 压缩：

    • 探测端：θ±ε 在世界里走的弧长是 R·cos φ·ε，越靠近极点探得越短，导数被低估。
    • 执行端：单位 θ 速率对应的切向速度模长也是 cos φ。

    两者相乘是 cos²φ：信息梯度一直存在，只是驱动不到。拖动下面的滑块看压缩有多快。

    选型
    不选把 φ 上限夹在 80°：只是不让相机进极区，问题还在，而且丢掉了顶视角。 不选只在执行端乘 sec φ：探测端仍然低估导数，只修了一半。 采用两端一起换：沿大圆做等弧长探测，用单位东/北切基积分；只在 spherical_rate 输出边界做一次 sec φ 换算（上限 20）。look-at 的 up 向量统一成 [−1,0,0]，跨极 roll 跳变从 180° 降到 0.20°。

    它是算法改动：改变了梯度在什么坐标里求、速度在什么坐标里积分。开关 nbv_policy.gradient_space，默认 angle（原版）。

    实验

    健康地图上（gaussian_th=0.005，见 04 章）、init φ=83.1°、50 步做 A/B，angle → tangent：

    0.24° → 51.5°
    方位行程
    223 → 0.7
    东/北速度各向异性
    25 → 4
    θ 振荡次数
    1 → 3 /18
    经度分区覆盖
    结论

    退化被修掉。但 10-17 发现这组 A/B 跑在全黑资产上（见 06 章）：各向异性这类纯几何量仍然成立，和信息增益大小有关的结论要重测。10-17 的消融里切空间没有质量收益，因为三个起点的轨迹基本不进入 φ>80° 的极区。

    2026-09-13 → 09-14 · commit ced24fa

    "梯度像抛硬币"的真因是一个剪枝阈值

    诊断超参数 · 配置错误成立（仿真）真机 config 仍是 0.7
    现象

    比较 angle 与 tangent 两种探测时出现"不可能"的结果：tangent 的梯度模长小于 angle，两者比值本应等于 sec φ，却在 φ=30° 和 88° 处变号。

    诊断 1后被推翻

    同一位姿重复打分完全一致，说明不是随机噪声；但在 grad_eps=0.01 的尺度上不光滑。φ=30° 取 12 个相距 0.5° 的基点，dF/dθ 4 正 8 负；噪声约为真实趋势的 6 倍。当时的结论是：把探测步长放大到 0.2。

    同日被推翻。用户问"如果有限差分和抛硬币一样，整个思路是不是可以扔了"。追查后发现测量用的地图只有约 180 个高斯，病因是地图密度，不是探测步长。
    诊断 2

    新高斯出生时不透明度是 0.5，而 densify_and_prune 用 gaussian_th=0.7 当 min_opacity。0.5 < 0.7，每个新高斯在下一次剪枝时都被删掉，除非优化先把它抬过 0.7。frame 4 一次剪枝 1117 → 124，之后 34 帧卡在 178 不动。

    选型
    不选放大 grad_eps 掩盖粗糙：治标，而且 10-18 的实验（12 章）证明大步长本身有害。 不选改出生不透明度：会改变建图初始化，影响面更大。 采用阈值改回标准 3DGS 的 0.005，只改仿真 config。真机那份会改变建图行为，要先验 PSNR。

    这是超参数改动：方法一行没变，只是一个数原本就设错了。

    结论

    同一个指标在健康地图上变成 12/12 一致，默认 eps=0.01 就够用。这一个数同时压住了重建质量和梯度质量，是"效果不好"最基础的根因。此后所有测量都先检查高斯数是在增长还是下降。

    2026-10-17 · commit d068bc4 · 53bfd1a · 96ba6a4

    给连续运动补上可行性、尺度和停止

    算法改进 ×4附带手设常数默认关闭，与原版逐位一致
    共同设计

    四项都做成 nbv_policy 下的独立开关，全关时在 447 步上与改动前的原版逐位一致。这样做有两个原因：消融时每次只动一个开关，贡献才分得清；真机出问题可以一键回退。

    可行性投影

    现象：相机冲向桌下、超关节限位。根因：目标函数里没有"可达"这一项，梯度不知道哪里去不了。

    不选只做硬夹紧：轨迹在边界上抖动，速度不连续。 不选在目标函数里加罚项：权重要调，而且信息峰仍在边界外拉着相机。 采用只削掉指令速度里"往外"的分量 v ← v − s·max(0, v·n)·n，往里走不受影响，激活度 s 在边界前 margin 内线性升到 1。Misimi 等人用的虚拟平面投影是同一思路。

    手设常数：φ 带 15°–80°、margin 8°。这是规则，不是由逆运动学推出来的。

    Fisher 掩码

    根因：打分对全部高斯求和。桌面和背景高斯的"信息"无法兑现，却在拉相机；它们大多没被看过，history≈0，分母只剩 λ=0.1，分数被放大。

    暂缓逐高斯 TSDF 光线投射算可见性：最有原则，但当前 TSDF 后端不暴露逐体素权重。 暂缓用实例分割选物体：要先解决"选哪个实例"。 采用ROI 盒外、支撑面以下的高斯权重置 0；相机低于支撑面时整幅打分乘 sigmoid 门。用支撑面近似遮挡。

    ROI 来源：仿真 = 真值物体包围盒（特权信息），真机 = 手设 tsdf.spatial_bounds。

    速率映射

    现象：同一个 fisher_step_scale 在不同场景下速度差两个数量级，原版 100% 的步数撞在限幅上。

    采用方向 = g/|g|，速率 = v_nominal·|g|/(|g|+κ)，κ = |g| 的滑动中位数。场整体放大 10⁴ 倍，指令完全不变（单元测试）。

    手设常数：v_nominal = 0.05 m/s、κ 窗口 20。v_nominal 有物理单位，限幅退回安全兜底。

    停止判据

    A 信息饱和、B 视角球覆盖、C 预算、D 停滞，满足任一即停。它自己迭代了两次：

    v1当前视角分数的滑动均值低于峰值的 10% 就停：贪心策略停在局部最优时当前分数也会衰减，会误停。 v2局部饱和只算提名，再给未覆盖的可达方向打分确认（53bfd1a）。 v3周期性 opacity reset 让所有视角同时塌缩，一次 run 在 reset 后两步误停，PSNR 9.6 dB；改为连续 2 次确认才停（96ba6a4）。

    手设常数：score_ratio 0.1、覆盖阈值 0.9 / 邻域 25°、confirm_checks 2。

    10-18 发现判据 A 的参照有问题。它拿"碗底"的分数作分母，按现在的写法几乎不可能触发，见 13 章。

    先修尺子：全黑资产、opacity reset 和评估视角

    实验设置 ×320 个 run 作废
    全黑资产

    现象：无地面时地图只有 631 个高斯，留出视角 PSNR 高达 58 dB。原因：instance_gs.ply 每个点的颜色都是 (0,0,0)。黑物体在黑背景上渲染，对高斯参数几乎没有梯度，Fisher 场里根本没有物体的信号；有地面时场几乎全由灰色地面驱动。

    做法：加 --recolor texture，给资产上确定性彩色纹理。已经跑完的 20 个 run 全部作废，9-13 的切空间 A/B 也跑在这个资产上。

    opacity reset

    3DGS 每 301 次迭代把不透明度全部置 0.01，几步内所有视角的 Fisher 分数同时塌缩。终态 PSNR 会取决于"最后一步离 reset 有多近"。消融配置里关闭它；真机保留，靠 confirm_checks 防误停。

    评估指标

    用 16 个不喂给建图的固定留出视角，并且只在物体像素上算 PSNR。原因：在训练视角上算 PSNR 会奖励"反复看同一处"；整幅图算会被大面积地面主导。另加表面完整度（GT 点 1 cm 内有高斯的比例）和视角球覆盖率。

    为什么单列

    这三项都没有改变方法，只改变了"测什么、怎么测"。但如果不修，算法改进的结论全都不可信。

    eps=0.05 的下侧探测点 17.1° 仍在带内，三次里也有两次往下走：大尺度上靠近桌面一侧本来就分数更高，大步长只是让梯度看见了这个趋势。

    可复现性

    第 0 步梯度符号在 3 次重复间一致的起点数：eps=0.01 为 3/3，更大的 eps 为 1–2/3。

    结论

    这是一次超参数实验，结论是不改。小步长并不更聪明：它跟随碗底的局部斜率，这个斜率总指向离开已访问轨迹的方向，在这里恰好朝北。如果将来需要更大的探测范围，探测点必须先夹到可行性带内（未实现）。

    不是分母在作怪，是分数围绕轨迹形成了一个碗

    诊断推翻"λ 假说"和"近视"
    λ 假说

    未观测元素（history < λ）约占掩码内参数元素的 18%，只贡献未覆盖方向分数的 30–39%，而且这个比例随时间从约 57% 降到约 20%。把 λ 放大 1000 倍，"最佳未覆盖 / 最佳已覆盖"只从 4.8 降到 2.8；只算已观测元素是 4.6。"先给目标函数加饱和"作废。

    碗

    把每个探测方向的分数除以当前视角，按它离最近已访问方向的角距离分桶：0–5° 处是 0.8 倍，15–25° 处已经是 62 倍，90° 以外是 2054 倍。增长主要来自已观测元素：从关键帧里斜着看过的元素，正面看时 log1p(cur) 大得多。

    当前位姿永远在碗底。所以停止判据 A 的"局部饱和"几乎必然成立，而"全局确认"拿碗外分数和碗底峰值比，碗深就有两三个数量级。09 章的 1.3–180 倍量的是碗深。在碗外两个方向之间公平比较，差距只有约 5 倍。

    覆盖上界

    300 步 × 约 0.024 m/s ≈ 0.71 m，在 0.89 m 的球上只是 46° 的弧。用与 StopMonitor 相同的 400 方向、25° 邻域算，一条最优 46° 大圆路径最多覆盖 0.275。实际 0.215–0.25，达到上限的 78–90%。覆盖低是路径预算所限，不是近视。这也和 Misimi 等人 Hybrid 只有边际收益一致。
